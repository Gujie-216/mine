# 树莓派上面向跟踪质量与帧时限的轻量化单目 ORB-SLAM3

**研究问题**　在相同输入、相同板卡和相近特征数量下，把计算留给定位困难的帧和图像区域，能否比固定减点更有效地降低跟踪延迟，同时维持定位精度与轨迹覆盖率？

**范围**　选用 ORB-SLAM3 v1.0-release、纯单目、CPU、离线回放和板端实时回放。主机型暂定 Raspberry Pi 4B 4 GB、64 位 Linux、主动散热；TurtleBot3 作为装有同款计算板和标定单目相机的地面采集平台。借到其他板卡时另立硬件组。本文是研究设计，现有二维激光仿真结果不能用于验证视觉方法。[上游发行版](https://github.com/UZ-SLAMLab/ORB_SLAM3/releases/tag/v1.0-release)

## 1　原版的成本在哪里

| 源码行为 | 板端可能出现的问题 | 如何证实 |
|---|---|---|
| 每帧构建尺度金字塔，各层按网格调用 FAST；首次为空的格子以更低阈值再检测 | 白墙等低纹理区域可能消耗两次扫描仍无有效点。降低最终点数也可能几乎不改变检测时间 | 分别记录金字塔、首检、复检时间，以及复检所获候选点数 |
| 候选点经八叉树分布，再计算方向和 ORB 描述子 | 稳定帧上大量描述子的边际价值低；直接固定减点又可能让转弯、遮挡后的跟踪难以恢复 | 同时记录实际描述子数、位姿优化后内点数及内点空间分布 |
| 跟踪与局部建图、闭环线程共享板端资源 | 插入关键帧或发生优化时，耗时长尾可能由后台竞争主导 | 按关键帧、回环、正常帧分组看跟踪 P95，同时采集全进程 CPU 时间、温度和频率 |

以上是待剖析的成本假设。先在板端跑原版，报告各阶段毫秒数与比例；若复检耗时很低，只做第一项改进。原版已经具备空间分布、双 FAST 阈值及专用初始化提取器，论文应给出与这些机制的直接对比。[特征提取源码](https://github.com/UZ-SLAMLab/ORB_SLAM3/blob/v1.0-release/src/ORBextractor.cc) · [跟踪源码](https://github.com/UZ-SLAMLab/ORB_SLAM3/blob/v1.0-release/src/Tracking.cc)

## 2　两项改进

### A　使用上一帧跟踪质量决定下一帧特征预算

在跟踪线程结束第 t 帧时，统计位姿优化后有效地图点内点数 I、4×4 图像网格中至少含两个内点的格子比例 C，以及最近五帧 TrackMonocular 耗时的中位数 L。用去畸变点计算 C 时，将图像边界转换到同一坐标系。三者都不需要第二遍特征匹配。处理第 t+1 帧前才使用该统计，禁止使用该帧的内点或真值。

以原配置正常跟踪预算 N 为基数，预置 1.0N、0.8N、0.6N 三档，各档保留原有尺度层比例。以下是开发集起点，可调后一次冻结：连续三帧 I≥80 且 C≥0.625，且 L>45 ms 时降一档；I<50、C<0.375 或状态异常，下一帧立即恢复全额；其他情况保持。降档后至少等待五帧再降，升档无等待。20 Hz 输入的一帧周期为 50 ms。模式切换与地图重置时清空历史。初始化沿用上游专用提取器及原切换条件；重定位后十帧使用全额正常预算。

预期收益在八叉树分配后的方向、描述子及下游匹配阶段。记录目标预算与实际点数，后者可能受纹理或树分裂影响。若内点集中在单面墙，即使总数高也应触发覆盖率保护。快速转向的首帧可能因上一帧反馈而低估难度，需专门统计切换后的失跟。

### B　限制空网格的低阈值复检

首轮高阈值 FAST 保留全部格子。逐尺度层收集首检为空的格子，按所属 4×4 图像区域的首检候选密度从低到高排列；同一区域内用轮换起点打破平局。稳定跟踪阶段每层至多复检一半空格，向上取整。连续帧轮换使同一纹理区域仍有再次被发现的机会。初始化、跟踪保护或上一帧质量未知时执行原版全部复检。B 单独启用时也能读上一帧的 I、C 和跟踪状态，无须开启 A。各层候选最终仍进入上游八叉树及描述子流程。

该改动直接减少第二次 FAST 调用。它也可能损失低纹理区仅存的角点，且两阶段遍历本身有成本。记录每层空格数、复检次数、复检新增候选数、进入最终描述子集合的复检点数与调度开销。若净耗时无收益或弱纹理测试恶化，单独报告负结果。

**与已有方法的关系。** 特征子集选择和主动匹配已有研究。这里考察的是提取前的跨帧预算和检测过程中的复检分配，两项策略能否在 ARM CPU 上优于固定预算，要靠延迟—误差曲线证明。投稿前补检近年的自适应 ORB、网格 FAST 和嵌入式前端论文，逐项比较输入信号、介入阶段、额外计算量和公开硬件实测。[Good Features to Track for Visual SLAM](https://openaccess.thecvf.com/content_cvpr_2015/papers/Zhang_Good_Features_to_2015_CVPR_paper.pdf) · [Good Feature Matching](https://arxiv.org/abs/2001.00714)

## 3　流水线与接口

标定的灰度图及时间戳 → 读取上一帧反馈和当前系统状态 → 选正常预算或初始化提取器 → 构建金字塔 → 各层网格首检与复检 → 八叉树分布、方向、ORB 描述子 → 原版运动模型或参考关键帧匹配 → 局部地图跟踪、位姿优化 → 保存内点与覆盖反馈。关键帧按上游规则进入局部建图、局部 BA、词袋检索和闭环线程。输出为相机位姿、稀疏地图、状态及逐帧日志。单目地图的尺度需外部参考才能用于米制导航。

## 4　试验矩阵

**数据划分。** EuRoC 只读 cam0 灰度图，20 Hz，禁用 IMU 和右目。MH_01_easy、V1_01_easy 用于剖析和调参；锁定其余九条为测试序列，覆盖机器大厅以及 Vicon 房间的不同速度、纹理和照明条件。保留初始化失败及多地图重启记录。公开记录数据清单、校准、时间戳文件校验和。EuRoC 来自飞行平台；地面适用性另用 TurtleBot3 验证。[EuRoC 数据与真值说明](https://projects.asl.ethz.ch/datasets/euroc-mav/)

**实机采集。** 同一相机与标定，固定分辨率、曝光策略和录制频率。采集走廊往返、快速转弯、弱纹理墙面三类路线，每类至少三次独立采集。各方法离线读取相同录像，另在板端按原始时间戳实时回放。优先使用同步动捕或经测量标定的外部相机提供真值，并报告外参、时间同步误差。仅有轮编码器时作辅助参考；没有独立真值的路线只报告覆盖、失跟、时延和恢复时间。

| 组 | 正常帧特征预算 | 空格复检 | 要回答的问题 |
|---|---|---|---|
| 原版 | N | 全部 | 未改动系统的精度与延迟 |
| 固定减点 | 0.6N、0.8N | 全部 | 只改一个参数能否达到同样效果 |
| 平均点数匹配 | 开发集上标定一个固定值，使实际平均点数接近 A+B | 全部 | 相同特征数下自适应调度是否仍有优势；公布测试集实际差值 |
| A | 跨帧预算 | 全部 | 减少描述与匹配的净收益 |
| B | N | 限额及保护 | 减少 FAST 复检的净收益 |
| A+B | 跨帧预算 | 限额及保护 | 两项改动是互补还是相互抵消 |

主试验每个方法、每条测试序列独立启动五次，同一轮以随机顺序运行各方法，登记顺序和进程配置。固定系统镜像、编译参数、OpenCV 线程数、板卡频率策略、散热、供电、分辨率与 Viewer 开关。每次从空地图启动。记录降频标志、温度、后台任务和峰值 RSS。另做一次全开关关闭的回归与日志开销验证。每轮启动时记录上下游 Git SHA、配置与编译器版本。六种设置加点数匹配组共七组，九条测试序列共 315 次基础回放。

**区分处理速度与实时性。** 全帧回放模式逐帧送入，报告 TrackMonocular 调用时间和端到端处理时间，排除人为 sleep，并单列初始化及重定位。实时模式独立按 20 Hz 生产帧，单槽队列用最新帧替换未处理的旧帧；分母为全部输入帧。分别报告采集到出位姿 P50/P95、超 50 ms 比例、丢帧率及有效位姿覆盖率。记录丢弃帧，禁止用丢帧换取表面上的高 FPS。时钟用单调时钟，ROS 采集时间须映射到同一时基。

**精度与鲁棒性。** 每帧导出相机中心、朝向、输入时间戳、地图 ID 和状态；用已标定外参把机体真值转成 cam0 真值，按时间关联（初始容差 5 ms，并记录未匹配数）。对有效同地图轨迹仅做一次 Sim(3) 对齐；报告平移 ATE RMSE（米）和间隔 1 s 的 RPE 平移（米）与旋转（度），RPE 使用同一全局尺度。只在有可靠姿态真值的序列报告旋转项。统计有效位姿帧数/输入帧数、首次初始化时间、重置次数、最长连续失跟时长。禁止拼接未合并地图后分段对齐再算整段精度。重置后未合并或覆盖不足 95% 的记录判为未完成，列入分母；可附最长片段精度但须标注长度。分别给出共同有效时间戳上的配对误差与各方法自身覆盖率。

**预先约定的工程判据。** 主比较为 A+B 对原版，全帧回放在板端的跟踪 P95 下降目标 ≥20%；平均配对 ATE 相对增幅的单侧 95% 上界 ≤10%，覆盖率下降 ≤2 个百分点，完整序列成功率不低于原版。以上是拟议目标，由导师在冻结协议前确认。每次先算单序列指标，同序列取重复运行中位数，再让各序列等权；按序列成对 bootstrap（10,000 次），不把数万帧当独立样本。ATE 比值使用基线与改进均完成的配对运行；给出排除数、每序列绝对米差、最坏序列与所有失败记录。九条序列给出的区间可能很宽；上界越界只说明本试验未证实精度非劣。A+B 必须同时与固定预算的延迟—误差曲线比较，若固定配置同样好，论文如实缩小贡献。

## 6　论文材料

**拟题**　面向嵌入式单目视觉 SLAM 的跟踪质量反馈特征预算与分区复检方法

**摘要（开题版）**　嵌入式移动机器人需要在有限 CPU 时间内持续输出位姿。固定特征预算难以同时适应纹理丰富的稳定运动和内点不足的快速转向。本文以单目 ORB-SLAM3 为基线，设计一种基于上一帧有效地图点数量、内点空间覆盖率和近期跟踪时延的分档预算策略，并在图像金字塔各层限制空网格的低阈值 FAST 复检。初始化及跟踪质量下降时恢复完整提取流程。研究拟在树莓派上使用 EuRoC 左目序列与 TurtleBot3 地面录像，比较原版、固定减点和两项策略的独立及联合效果。评价同时考察轨迹误差、有效位姿覆盖率、跟踪延迟长尾和实时丢帧率，以检验在预设精度容差内降低计算负担的条件，并分析弱纹理和急转弯下的失效边界。

**关键词**　单目视觉 SLAM；ORB-SLAM3；嵌入式机器人；自适应特征预算；FAST 角点；轨迹评测

**章节安排**

1. 引言。从 20 Hz 相机的 50 ms 周期引出问题，明确板卡、定位容差及两条研究假设。
2. 相关工作。分别梳理检测前预算、检测中候选选择、匹配阶段特征选择与后端减负；表格列出决策阶段、所需输入与额外开销。
3. 基线与瓶颈。给出上游版本、板端分阶段耗时、首次与二次 FAST 的命中率，说明选择这两处修改的依据。
4. 方法。给出预算状态机、尺度配额、复检顺序、保护条件、最坏回退成本和伪代码。
5. 实验设计。公布硬件、数据划分、对照与消融、时间关联和坐标变换、非劣界及失败定义。
6. 结果与讨论。按序列报告误差—延迟曲线和置信区间；用困难片段展示预算、覆盖、失跟及温度随时间的变化；讨论单板单相机和场景数量的限制。
7. 结论。只写实测支持的收益、适用条件以及下一步迁移范围。

**贡献句式。** 方法贡献写“在提取前使用上一帧地图点内点、空间覆盖与跟踪耗时选择下一帧逐层预算，并在失跟后回退”。机制贡献写“在首轮 FAST 后按空间支持度分配空格复检，以复检次数、入选点数和耗时解释收益”。验证贡献在实验后填入“在［板卡］的［序列数］条独立测试序列上，相对［原版／匹配点数基线］，P95 变化［数值］，ATE 配对上界［数值］，完整运行［分子/分母］”。固定减点已经能实现的收益不能归因于新策略。

**投稿定位。** 若完成单板复现和完整消融，适合机器人系统实现、移动机器人感知方向的学生研究论坛或嵌入式视觉 workshop 短文；投稿前核对当届是否正式收录。若有跨场景板端结果、独立真值地面实测、同预算强对照和失败分析，可考虑机器人系统应用类期刊，如 Journal of Intelligent & Robotic Systems。若只有参数调整和桌面平均 FPS，先作为大创阶段报告。录用取决于实测证据、相关工作区分及当期征稿范围。[期刊范围](https://link.springer.com/journal/10846)
